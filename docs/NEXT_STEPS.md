# 后续工作优先级与扩样方案

## 求职准备顺序

1. 能独立运行和解释主项目：Python变量/函数/路径/模块、pandas分组和图、S/T/X、HT、配对区间和验证选择。
2. SQL熟练度：本项目的约束/join/窗口/聚合只是可展示起点，还要独立练习常见多表、去重、漏斗、留存、日期窗口题。Criteo没有时间/事件序列，不在这里伪造真实留存分析。
3. 能从业务问题定义指标、估计目标、预算约束和线上实验设计；能解释负结果与下一步决策。
4. 如果仍有时间，做一次协议清楚的扩样检验；再做IHDP观察研究附录。

## 1398万原始数据已经处理到什么程度

已全量流式审计、分组统计与ATE汇总。模型主实验只使用随机抽取的100万行。已有CLI支持更大sample-size和全量模式，但并未运行，不能写成“全量模型已完成”。

大规模训练是否值得，取决于它是否回答额外问题。当前训练control转化164个，扩样可能改善信号，但已做的0.25/0.5/1.0开发学习曲线没有证明X的相对收益持续改善。因此扩大规模是一项验证，而不是预先承诺提升。

## 建议的下一轮协议（尚未实施）

目标：比较更大训练数据对20%预算结果、X相对强基线的配对差、AUUC/Qini和训练成本的影响。

- 先冻结候选模型/复杂度、seed、主预算、开发指标、停止条件和资源预算。
- 记录已查看的旧1M样本行号；未来确认性holdout从未进入模型开发的新行中选，并隔离这些旧行。完整数据的聚合审计已看过，不能称没有任何先验观察。
- 可从原1M之外固定约2M的新行作为锁定holdout，在其余行中固定训练/validation；最终holdout只在开发选择冻结后评价。
- 用嵌套训练子集比较1M、3M、5M，保持validation固定、评价人群一致。不要用不同test子集的点估计高低判定规模作用。
- 记录每臂人数与conversion事件数、20%效果与差值CI、AUUC/Qini、拟合时间和实测峰值内存；重复seed的离散度不冒充独立试验CI。
- 只有出现值得确认的开发证据或明确的全量部署需要，再考虑进一步扩大，而非必须训练全部1398万行。

**当前 `run_pipeline.py --sample-size 5000000` 只执行普通新抽样/新划分，没有自动实现上述“排除全部旧1M、固定新holdout”的确认性协议。** 直接跑它可作探索，但不能据此声称新独立验证。上述更严格协议需要下一阶段新增实现。

## 观察研究最小完成范围

按 `因果推断理论/补充/观察研究/` 五份笔记，采用固定来源IHDP版本，先naive/OR/IPW/AIPW，再T/X/DR，带OOF nuisance与oracle测试。报告overlap、ESS、调整后SMD、ATE error、root-PEHE和同预算regret，明确连续outcome单位。

不要把DragonNet、CEVAE、R learner、TMLE、DID、IV全部加入同一轮。先有清楚识别问题与可复核结果，未运行的内容仅放roadmap。
