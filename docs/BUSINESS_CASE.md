# 业务实现、实际结果与可执行决策

## 1. 从业务到估计目标

问题是广告资格容量有限时，如何为合资格人群选人。当前假设每次资格分配的成本相同、每次转化价值相同；约束为恰好选择 20%，不是人民币预算、竞价最优或收入最大化。

潜在结果框架下，相对全不处理的策略增量是 $\Delta V(\pi)=E[\pi(X)\tau(X)]$。主 outcome 为 conversion；visit 用于结果可学习性辅助诊断。treatment 表示资格分配，exposure 表示其后的实际实现，二者不能混用。

公开匿名字段没有业务含义，不能编造年龄/收入/会员人群画像。原始线上增量也不能由隐私处理后的公开文件直接还原。

## 2. 从输入到交付的实际流程

| 步骤 | 实际完成 | 对业务判断的作用 |
|---|---|---|
| 全量读取 | 13,979,592 行、16 字段流式审计；缺失/非有限值、标签、曝光逻辑、重复指纹 | 确认输入基本可用，记录匿名重复限制 |
| 统计汇总 | 全量两臂人数、conversion/visit 率、ATE/SE/CI | 描述公开实验整体效果，不伪装原业务线上收益 |
| 开发样本 | 全文件等概率无放回 100 万行，随机 seed42 | 控制计算成本，避免只读文件头造成偏差 |
| 划分 | T×conversion 分层60/20/20，训练内拟合预处理 | 防止验证/测试参与拟合 |
| 诊断 | SMD/KS、train 中20k C2ST、99置换与Holm；visit/conversion可学习性 | 查已观测异常与建模信号；不把不显著当证明随机 |
| 候选 | S/T Logistic、T/X XGBoost；解析随机、response基线 | 比较简单/复杂模型与强业务基线 |
| 选型 | validation的20%HT；最终response，uplift候选中S | 用预算目标选，选择先于test |
| 评价 | test20%及辅助预算；AUUC/Qini/校准；配对臂内bootstrap | 给效果及差值的不确定性 |
| 稳健性 | 排除旧test，3seeds×3嵌套规模+3groupfull，48拟合 | 检查开发划分/规模/可见重复敏感性 |
| SQL | SQLite派生表，主外键/1:1join/条件聚合/窗口排名 | 可复核地验证计数和策略估计 |
| 交付 | 冻结本地模型、评分脚本、结果表、Notebook、报告 | 输入新特征可生成离线预算名单 |
| 业务验证 | 同预算策略A/B方案、功效和假设经济场景 | 明确进入真实业务还需要什么证据 |

## 3. 主结果与行动

validation选中的response在20万test行上，每10万待选人的增量估计为117.23，随机策略24.61；差92.61，配对95%CI [50.02,132.15]。这是公开样本固定模型的offline结果。

S相对response差6.10，CI [−1.77,14.61]；X差−7.11，CI [−31.51,18.64]。没有足够证据为了uplift模型的名字替换冻结基线；另一个模型的test点估计更高，也不改变事先选择。

这对应当前行动：保留已选择基线作为离线候选，在真业务里与既有策略做预注册同预算实验。复杂模型只有在独立证据支持增益、成本合理且稳健时才值得引入。

## 4. 规模与稀疏事件

全量数据已被扫描处理过。**尚未完成的是全量模型训练**，不是完全没处理其余数据。

100万样本的600k训练行里，control约89,754人、仅164个conversion；test对照事件55。完整row开发训练规模三个seed平均主指标response127.51、S126.67、X99.03，跨seed样本标准差分别4.54、5.09、5.93。标准差不是CI，切分共享数据。

X在12个开发配置中均低于response，但学习曲线没有证明唯一原因是样本不足。过拟合、超参数、效应结构和特征信息都可能影响结果。

若做扩样，建议先用3—5百万作为一个预定规模检验，固定评价人群、模型配置与成本记录，并留出未进入建模的新行。不要每次重抽test再挑最好的一轮。全量审计的聚合信息已经被查看，新增方案也已受前期结论影响，因此不能声称完全没有分析者选择影响。

全量训练不是简历或GitHub的硬条件；如果做，需要足够内存、合理的额外证据和可比评价。仅12列float32特征矩阵就约640MiB，算法、DataFrame、伪标签、预测、重复模型和复制会额外占内存；CSV大小不是峰值内存。

## 5. 线上实验还缺什么

真实用户随机单元、候选池、触达成本、转化/归因窗口、贡献毛利、频控与负反馈日志。新实验随机的是策略臂，各臂按相同约束选20%，比较全部入组用户的结果；只比较被选中的两批人会混入选择构成差。

固定策略和窗口、样本量、主指标/护栏、停止规则；若流量/供需有干扰，考虑合适簇或switchback设计。当前的planning只是输入明确假设的数值计算，没有真实线上实验状态。

## 6. 能展示什么与尚未展示什么

已展示业务问题转数学目标、实验诊断、模型实现、预算评价、不确定性、SQL复核、规模敏感性与结论边界。没有真实事件日志的漏斗/留存/日常指标异动归因，没有真实画像或部署服务验证。

未来IHDP补充观察数据的识别/调整与oracle误差，不替代这些业务数据能力。当前主项目可以作为公开benchmark项目展示；面试中的可信度依赖能独立解释和改动关键代码。
